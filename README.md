# 本地赛道计次裁决台

一个完全本地运行的赛道计次（lap counting）裁决工具：录入 1～3 名选手、两段合格耗时区间与至多 40 条感应记录，自动为每名选手选出最优的完整计次方案。

- 后端：Python + FastAPI（`app/`）
- 前端：原生 HTML / CSS / JavaScript，无构建步骤（`static/`）
- 裁决算法：枚举合法趟 + DAG 动态规划（`bisect` 二分前驱），含 400 组随机数据对拍测试

## 裁决规则

每趟从同一选手的感应记录中依次选取 **起点 S → 中途门 M → 终点 F** 各一条：

1. 两段耗时（M−S、F−M）都必须落在录入的**正整数闭区间**内；
2. 同一选手的不同趟**不得共用任何记录**；
3. 后一趟的起点秒数必须**严格晚于**前一趟的终点秒数（`后起点 > 前终点`）；
4. 其余读数一律舍弃，列入“未采纳记录”。

记录可以乱序录入，同一秒允许存在多条记录。

### 记录秒数（任意大的非负整数）与页面精度

- 记录秒数是**非负整数，位数不限**：允许超过 JavaScript 安全整数范围（2^53）的秒数，如起点 `9007199254740992`、中途门 `9007199254741003`、终点 `9007199254741014`，取值范围不会因页面而缩小；
- 后端按任意精度整数接收秒数（JSON 整数或十进制字符串均可）并精确计算两段耗时；前端从响应解析、页面展示、两段差值计算、名次表用时而到**人工复核绑定**，秒数及其差值全程以**规范十进制字符串**保存与比较（差值用 `BigInt` 计算，不经过 `Number`），不发生任何浮点截断；前导零等值写法（如 `"0011"` 与 `"11"`）归一；
- 因此，即使两条记录秒数相差极小、且秒数本身已超过 2^53（例如两段各 11 秒：…40992 → …41003 → …41014），页面显示的两段耗时仍是精确的 **11 / 11 秒**，不会被算成 12 / 10。

> 复现（修复前）：两段区间均填 10～60 秒，选手 101 录入 S/M/F 三条记录，秒数依次为 `9007199254740992`、`9007199254741003`、`9007199254741014`，裁决得到一趟、两段各 11 秒。给该趟保存“通过”和备注后，**添加一条空记录行**（或重排记录行）触发重算：旧实现把秒数经 `Number` 截断（中途门被截成 `9007199254741004`），两段差值在复核绑定核对中变成 12、10，于是绑定被误判失效，状态变回**未复核、备注消失**，页面展示的秒数也被改写。修复后：秒数与两段差值在响应处理、页面展示和复核绑定判断中始终精确；绑定未变且仍采纳的趟，重排记录、增删无关记录（含空行）与手动重算都保留复核。

### 选手编号约定（任意大的正整数）

- 编号是**正整数，位数不限**：允许超过 JavaScript 安全整数范围（2^53）的大编号，如 `9007199254740992` 与 `9007199254740993`；
- 编号从输入、API 请求/响应到结果展示、罚秒归属、名次表编号排序、人工复核绑定**全程无损**：前端以十进制字符串原样发送与解析（不经过 `Number` 截断），后端按任意精度整数处理，两个相差 1 的大编号不会被混同；
- **前导零等值写法视为同一编号**：`007` 与 `7`、`09007199254740992` 与 `9007199254740992` 是同一个编号，改写写法**不算改号**，不会触发罚秒释放或复核失效；
- 不同编号的罚秒与复核**互不影响**；真正改号或删行时原编号罚秒立即释放、复核按原绑定规则立即失效（输入非法、防抖合并、请求在途都不会延迟失效），改回不恢复。

> 复现（修复前）：录入选手 `9007199254740992` 与 `9007199254740993` 并裁决，两人编号曾显示相同，给前者保存 7 秒与原因会同时影响后者；仅有前者时把编号改成后者，旧处罚也不会立即清除。修复后以上场景均按两个不同编号正确处理。

每名选手按以下优先级选择方案：

1. **完整计次数最多**；
2. 计次数相同时，**各趟用时之和最短**（每趟用时 = 终点秒数 − 起点秒数）；
3. 仍相同时，取按计次时间顺序串接的记录 ID 序列**字典序最小**者。

没有任何完整一趟时显示 **0 次**；输入非法时只报错、**不展示任何部分结果**。修改任意输入（耗时区间、选手、感应记录，含增删行与载入示例）后，页面会按当前完整输入**自动重算所有选手**，无需再点按钮；连续编辑会合并为一次重算，“⚖ 裁决 / 重新计算”按钮仍可随时手动触发。输入非法时只显示错误，改回合法值后自动恢复裁决；等待响应期间可继续编辑，只有仍适用于当前输入的响应才会更新结果或错误。

## 页面用法

1. 填写两段合格耗时闭区间（正整数秒）；
2. 添加 1～3 名选手，编号必须互异；
3. 录入感应记录：唯一字符串 ID、选手编号、门（S/M/F）、非负整数秒数；全空行会自动忽略，部分填写视为非法；
4. **无需点击按钮**：修改任意输入（区间、选手、记录，增删行、“填入示例”）后，页面会立即清除旧结果并按当前完整输入自动重算所有选手，结果按选手分卡展示每趟采纳的三条记录与两段/总用时，以及该选手所有未采纳记录。连续编辑会合并为一次重算；输入非法时只显示错误，改回合法值后自动恢复结果。“⚖ 裁决 / 重新计算”按钮仍可随时手动立即重算。
5. “填入示例”可快速载入一份包含多趟、乱序、舍弃读数的数据（载入后自动重算）；“清空”会同时清除输入、结果与错误，此前发出的请求随后返回也不会恢复它们。
6. 合法结果顶部展示**比赛名次表**，可在名次表下方为每名选手保存罚秒与原因，保存后名次立即重排，无需重新裁决；详见下节。

## 比赛名次与罚秒（仅本次页面会话）

合法裁决结果顶部展示**比赛名次表**，列出每名选手的 **选手编号、计次数、原总用时、罚秒、调整后用时、名次**：

- **调整后用时 = 原总用时 + 罚秒**；
- 有完整计次的选手按 **计次数降序、调整后用时升序** 排名；两项都相同者**共享名次并跳号**（如 1、1、3），并列按编号升序展示；
- 计 0 次的选手排在末尾，按编号升序，**无名次**（显示“—”）。

名次表下方可为每名选手保存 **非负整数罚秒**（默认 0）与 **至多 200 字** 的原因；**罚秒大于 0 时原因必填**。校验失败时保存不生效，**保留原已保存的罚秒与原因**；保存成功后名次表**立即重排，无需重新裁决**。

- 罚秒**只影响名次表**：不改变采纳记录、计次数、裁决用时与人工复核，也不会发送到服务器；
- 罚秒仅保存在页面内存中，**刷新页面即全部清除**（不写入 localStorage 等任何持久存储）；
- 修改感应记录或耗时区间会**保留**已保存的罚秒；
- **任一选手行改号或删除时，在触发输入事件的当下立即清除该行原编号的罚秒与原因**——不必等待重算，也不论另一行是否仍占用同一编号（例如把 101 行临时改成 102 造成重号、再把原 102 行改为 104：原 102 行离开 102 的那一刻，102 的罚秒立即清除，不会因 101 行仍填着 102 而残留）；输入清空或非法（如重号）时同样立即清除。之后把编号**改回**、或删除后**重新添加同编号**，该编号也只显示默认 **0 秒、空原因**，旧罚秒不会随重算、过期响应或任何后续编辑恢复；未改号、未删除选手的处罚不受影响；
- “清空”与“填入示例”会同时清除全部罚秒；
- 输入非法或等待重算期间名次表隐藏；过期（已失效）的响应不会恢复名次表；最新合法结果总是套用当时已保存的罚秒。

## 人工复核（仅本次页面会话）

每趟已采纳计次下方都有“人工复核”区：可将该趟标记为 **未复核 / 通过 / 存疑**（默认未复核），并填写至多 **200 字**备注，点击“保存复核”生效。选择“存疑”时备注必须非空；备注超长或存疑无备注会保存失败，并**保留原已保存的复核内容**不变。

- 复核只是人工标注：**不改变**采纳方案、计次数与用时，也不会发送到服务器；
- 复核仅保存在页面内存中，**刷新页面即全部清除**（不写入 localStorage 等任何持久存储）；
- 复核按“选手编号 + 三条记录的 ID/门/秒数 + 该趟两段耗时 + 两段耗时区间”绑定到具体的趟，**不按趟序号或记录行号定位**；其中编号、秒数、两段耗时与区间都以规范十进制字符串精确比较（差值用 `BigInt` 精确计算），秒数超过 2^53、或两段差值小到 11 秒时也不会因浮点截断而误判。每次修改输入都会逐条核对已保存的复核，失效逐趟独立判定，一次编辑不会清空无关趟的复核：
  - **任一绑定值改变**（修改选手编号或两段耗时区间，或修改绑定记录的 ID、门、秒数），或**绑定记录、绑定选手被删除**，对应复核在输入变更的**当下立即丢弃**——不必等到返回合法裁决，即使当前输入非法、尚在防抖合并、或上一次请求仍在途也一样；之后再把值改回（例如下限清空触发非法报错后填回原值，或在防抖提交前改动后立即改回），该趟也只会显示**未复核、空备注**，旧状态与旧备注**不会恢复**；
  - 绑定值未变时（重排记录行、增删或修改无关记录、手动重新计算），只要该趟仍被最新合法裁决采纳，复核**原样保留**；最新合法裁决不再采纳的趟继续清除；过期响应（含非法响应）同样不能恢复已丢弃的复核；
- 输入非法或等待重算期间复核编辑区会隐藏；过期的响应不会覆盖正在编辑的新备注；
- “清空”与“填入示例”会同时清除全部复核记录。

## API

`POST /api/adjudicate`

```json
{
  "standards": {"smMin": 10, "smMax": 60, "mfMin": 10, "mfMax": 60},
  "runners": [{"number": 101}, {"number": 102}],
  "records": [
    {"id": "a1", "runner": 101, "gate": "S", "time": 0},
    {"id": "b1", "runner": 101, "gate": "M", "time": 12},
    {"id": "c1", "runner": 101, "gate": "F", "time": 25}
  ]
}
```

- 合法：`200 {"ok": true, "result": {...}}`
- 非法输入：`422 {"ok": false, "error": "中文原因"}`（不返回部分结果）
- 请求体不是 JSON：`400`
- 编号字段（`runners[].number`、`records[].runner`）接受 JSON 整数或十进制字符串，**可为任意大的正整数**（如 `9007199254740993`）；响应中的 `runner` 以精确 JSON 数字原样返回，不截断、不缩小编号范围。前导零等值写法（如 `"007"`）按数值归一。
- 秒数字段（`standards.*`、`records[].time`）接受 JSON 整数或十进制字符串，**可为任意大的非负/正整数**（如 `9007199254741014`）；响应中的各 `time`、`smTime`、`mfTime`、`totalTime` 以精确 JSON 数字原样返回，字段、字段类型与状态码均不受影响。前端对这些值做十进制字符串无损处理，秒数再大也不会缩小取值范围或截断差值。
